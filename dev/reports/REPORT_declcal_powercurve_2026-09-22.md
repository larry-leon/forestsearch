# REPORT — declcal power curve: fixed-k and calibrated declaration rates, size beside power

Read-only post-processing of the committed declcal payloads. There was no simulation, no `R/` change, and no push.
The table is in `quarto/simulations/gbsg_020/scripts_dinamr/logs/declcal_powercurve.txt`.

## What was computed

- **Source:** `quarto/simulations/gbsg_020/results/declcal_{bnull,inull,power}_*_res_1_2000.rds`.
  - There are 13 cells, each with R = 2000 replicates.
  - Every replicate has `status == "ok"`, and none of `max_T_pre` or `Mstar_q{90,95,99}` is NA.
- **Rules:**
  - **Fixed k:** the rate is `mean(max_T_pre >= k)` for k in {1.6449, 1.8, 2.0, 2.2, 2.4, 2.6, 2.8, 3.0, 3.2, 3.4, 3.6}.
  - **Calibrated:** each replicate is compared with its own cutoff, `max_T_pre >= Mstar_q90 / q95 / q99`, for α = 0.10, 0.05 and 0.01.
- **Intervals:** Wilson 95%, with z = qnorm(0.975).
- **Boundary-null column:** each row also shows the rate under the same rule in the complete-null cell with the same n: n 500 uses A1, n 1000 uses A2, and n 1500 uses A3. Size and power can therefore be read on one row. In the A rows, this column repeats the row's own rate.

## Cross-checks

- **Calibrated rates:** the α = 0.05 and α = 0.10 rates match the `declared_cal05` and `declared_cal10` rates in
  `declcal_findings.txt` §7.1 digit for digit, in all 13 cells. In every replicate, `declared_cal05 == (max_T_pre >= Mstar_q95)`, and the same holds for `cal10` with `Mstar_q90`. Also, `Mstar_q95` is identical to `kappa_hat_05`.
- **The k = 1.6449 row is not the §7.1 "conventional (exact z)" column.**
  - `declared_conv_exact` equals `max_T_post >= qnorm(0.95)`, so it uses the post-reduction family, after the d0/d1 floors. Where the post family is empty, `max_T_post` is NA.
  - This table uses `max_T_pre`, the pre-reduction family, as the task specifies.
  - The two rates differ by 0.0000 to 0.0335; B4 has the largest gap (0.2500 vs 0.2165), followed by B1 (0.1220 vs 0.0905).
  - Using k = 1.6449 or qnorm(0.95) gives identical rates in every cell.

## Reading

- **Complete null (A1 to A3).**
  - The fixed-k size is 0.92 to 0.94 at 1.6449, and it first falls near 0.05 only at about k = 3.5. At k = 3.6 it is 0.033 to 0.041.
  - The size curve is essentially flat in n.
  - The calibrated rules hold their nominal level:
    - α = 0.05: 0.043 to 0.049;
    - α = 0.10: 0.084 to 0.105;
    - α = 0.01: 0.009 to 0.0115.
- **Uniform benefit (B1 to B6).** The rates fall well below the matched complete-null rates at every k. Every calibrated rate is at most 0.0005 (at most 1 of 2000). These DGMs sit inside the null, not on its boundary.
- **Planted harm HR 1.5 (C1 at n 1000, C2 at n 1500).**
  - **C1:** at every fixed k from 1.6449 to 3.2, the rate is *below* the matched A2 size. The two are equal at 3.4 (0.0740 each), and C1 is marginally above at 3.6. Its calibrated rate equals A2's calibrated size at α = 0.05 (0.0495 vs 0.0490). **At n 1000 there is no usable power at any cutoff on this grid.**
  - **C2:** it crosses A3 between k = 2.6 and 2.8. The largest separation on the fixed-k grid is at 3.6, with 0.0855 against 0.0330. At calibrated α = 0.05 the rate is 0.0935 against 0.0430.
  - **Caveat for reading C1 and C2:** the C DGMs combine a harm subgroup with benefit in its complement. The complement's benefit pulls down the spurious part of the maximum, so a low-k C rate below the A rate is expected and is not a defect.
- **Planted harm HR 2.0 (C3 at n 1000, C4 at n 1500).**
  - At k = 3.6: 0.3475 and 0.6375, against sizes of 0.041 and 0.033.
  - Calibrated at α = 0.05: 0.355 and 0.641.
  - Calibrated at α = 0.01: 0.191 and 0.437.
- **Calibrated rule vs a fixed cutoff.** At α = 0.05, the calibrated rule behaves like a fixed cutoff of about k = 3.55. Its power sits between the k = 3.4 and k = 3.6 rows in every C cell, which fits the median `kappa_hat_05` of 3.58 to 3.59 in the C cells. **Per-replicate calibration therefore buys size control, not extra power over a well-chosen fixed k.** On this grid, a fixed k would have to be about 3.5 or higher for its complete-null size to reach 0.05.

## Reproduction

The table was generated by the script below, run with `Rscript` from any working directory. It reads the payloads only.

```r
setwd("quarto/simulations/gbsg_020")   # from the repo root
files <- sort(Sys.glob("results/declcal_*_res_1_2000.rds"))
wilson <- function(x, n, z = qnorm(0.975)) {
  p <- x / n; d <- 1 + z^2 / n; ctr <- (p + z^2 / (2 * n)) / d
  hw <- z * sqrt(p * (1 - p) / n + z^2 / (4 * n^2)) / d
  c(p, max(0, ctr - hw), min(1, ctr + hw))
}
K <- c(1.6449, 1.8, 2.0, 2.2, 2.4, 2.6, 2.8, 3.0, 3.2, 3.4, 3.6)
dec <- function(r) cbind(sapply(K, function(k) r$max_T_pre >= k),
                         r$max_T_pre >= r$Mstar_q90, r$max_T_pre >= r$Mstar_q95,
                         r$max_T_pre >= r$Mstar_q99)
## per cell: wilson(colSums(dec(r)), nrow(r)); bnull column = same for A1/A2/A3 matched on r$n
```
