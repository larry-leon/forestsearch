## OPEN ITEMS

1. **`fs_mr_oc_summary()` still uses npv = 1 for a non-detected replicate** (`R/fs_mr_oc_summary.R:56`, `:308-309`; `man/fs_mr_oc_summary.Rd:83`).
   - Its "unconditional" convention is documented as matching `build_classification_table()` and León et al. (2024), Table 1. For NPV under an alternative it no longer does: the extractors now store |Hc|/N.
   - It reads MR batch payloads, not `run_simulation_analysis()` output, so no stored value changes. But its unconditional NPV now disagrees with the `build_classification_table()` / `format_oc_results()` averages for the same replicates. Its spec fill (1) agrees.
   - `tests/testthat/test-fs_mr_oc_summary.R:108` pins that convention (0.85 = (0.7 + 1)/2).
   - Out of scope here (`R/fs_mr_oc_summary.R` is listed as do-not-touch).
2. **`build_classification_table()` fills a missing npv with 1 when `any.H == 0`** (`R/simulation_tables.R:372`).
   - This is the old convention. It is reached only when `spec`/`npv` are NA, that is when `harm_col` is absent or the results come from another producer. For extractor output with `harm_col` present it does nothing.
   - The comment at `:366` says the extractors store NA for sens and ppv when `any.H = 0`; under an alternative they store 0.
   - Out of scope (`R/simulation_tables.R`).
3. **Site 2 returns `any.H = 1` with `size.H = 0`** (`R/run_simulation_analysis.R:1041`, set before the `M.*` loop and not reset in the site-2 fallback).
   - A detection rate averaged from `any.H` counts such a replicate as found.
   - The test deliberately leaves `any.H` unchecked at site 2.
4. **ppv on an empty identified set: 0 on the no-find path, NA on the found path.**
   - The no-find path stores ppv = 0 under an alternative, while the found-case formula gives 0/0 = NA.
   - A replicate whose identified set is empty but which takes the found path (rows, but `treat.recommend` all 1) gets ppv = NA. The averages then drop it (`na.rm`), while a no-find replicate counts as 0.
   - spec and npv now agree on both paths. ppv was out of scope ("Do not change `out$ppv`").
5. **Degenerate alternative with every patient in H (|Hc| = 0).** The new code stores spec = 1; the found-case formula gives 0/0 = NA. npv = 0 agrees. This case is unrealistic and is listed for completeness only.
6. **NEWS heading** reads `0.4.1.9002 (development)` while `DESCRIPTION` is 0.4.1.9004. It already lagged at 9003, and the task does not ask to change it.
7. **The A-002 baseline report is not in this repository** (§4). The figures used are the ones recorded for that run in the session notes.
8. **Tracked renders and payloads are unchanged**, as the task directs: no render, simulation or application re-run.
   - The 17 tracked renders the audit lists (`quarto/simulations/actg175/binary_methods/` 16, `binary_legacy/` 1) keep the old H1 specificity/NPV averages until Larry decides otherwise.
   - Per the audit, 126 source files average these columns.
9. **Test hygiene.** The data helper calls `set.seed(1)` without restoring the global RNG state, the same pattern as the A-002 test. The asserted values do not depend on it, because `flag_harm` is deterministic. `withr::local_seed()` would keep it local.
